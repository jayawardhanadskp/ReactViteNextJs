# Next.js 02 — Project Anatomy and File-based Routing

> Flutter go_router: you write a list of routes in code.
> Next.js: **folders are routes**. You create a folder + a `page.tsx` file, and the URL exists.

## 1. Project structure

```
my-next-app/
├── app/                      ← ROUTES live here (App Router)
│   ├── layout.tsx            ← root layout: <html> and <body>, wraps every page (required)
│   ├── page.tsx              ← the page for "/"
│   ├── globals.css           ← global CSS (Tailwind is imported here)
│   └── favicon.ico
├── public/                   ← static files served as-is: /logo.png → public/logo.png
├── next.config.ts            ← Next.js configuration
├── package.json              ← scripts: dev, build, start, lint
├── tsconfig.json             ← TypeScript (with the "@/*" import alias)
├── eslint.config.mjs         ← lint rules (includes React hooks rules)
└── next-env.d.ts             ← generated types (don't edit)
```

You add your own folders next to `app/`, for example:

```
├── components/               ← reusable UI components
├── lib/                      ← data access, server actions, helpers, types
└── data/                     ← (in our project) a JSON file used as a tiny database
```

`@/` means "project root": `import { RecipeCard } from '@/components/RecipeCard'`.

## 2. Folders = URL segments, `page.tsx` = the screen

```
app/
├── page.tsx                      →  /
├── about/
│   └── page.tsx                  →  /about
├── recipes/
│   ├── page.tsx                  →  /recipes
│   ├── new/
│   │   └── page.tsx              →  /recipes/new
│   └── [id]/                     ←  [square brackets] = dynamic segment
│       └── page.tsx              →  /recipes/pol-roti, /recipes/kottu, ...
└── api/
    └── recipes/
        └── route.ts              →  /api/recipes   (an API endpoint, not a page)
```

**A folder without `page.tsx` is not a public URL.** You can put components inside route folders
safely. Only `page.tsx` (UI) or `route.ts` (API) make a URL.

The page file must **default export** a component:

```tsx
// app/about/page.tsx
export default function AboutPage() {
  return <h1>About us</h1>
}
```

## 3. Special files

Inside any route folder, these file names have special meaning:

| File            | Purpose                                                    | Flutter feeling                     |
| --------------- | ---------------------------------------------------------- | ----------------------------------- |
| `page.tsx`      | the UI for this URL                                        | a screen                            |
| `layout.tsx`    | UI that **wraps** this page and all child pages; keeps state across navigation | `ShellRoute` + `Scaffold` |
| `loading.tsx`   | shown instantly while the page loads (Suspense fallback)   | `FutureBuilder` waiting state       |
| `error.tsx`     | shown when rendering throws an error (error boundary)      | `ErrorWidget.builder`               |
| `not-found.tsx` | shown when you call `notFound()` or no route matches       | `errorBuilder` in go_router         |
| `route.ts`      | an API endpoint (GET, POST…) instead of a page             | a backend endpoint                  |

How they nest (for one route segment):

```tsx
<Layout>
  <ErrorBoundary fallback={<Error />}>
    <Suspense fallback={<Loading />}>
      <Page />              {/* or <NotFound /> */}
    </Suspense>
  </ErrorBoundary>
</Layout>
```

## 4. Layouts

```tsx
// app/layout.tsx — ROOT layout (required; must have <html> and <body>)
import Link from 'next/link'
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <nav>
          <Link href="/">Home</Link> · <Link href="/recipes">Recipes</Link>
        </nav>
        <main>{children}</main>          {/* the current page goes here (like <Outlet />) */}
      </body>
    </html>
  )
}
```

Layouts **nest**. `app/recipes/layout.tsx` would wrap only the `/recipes/...` pages, inside the root layout:

```
RootLayout
└── RecipesLayout          (app/recipes/layout.tsx — e.g. a sidebar with categories)
    └── page               (app/recipes/page.tsx or app/recipes/[id]/page.tsx)
```

When you navigate between `/recipes/a` and `/recipes/b`, the layouts **don't re-render** and keep
their state (a search box in the layout keeps its text). Like a `ShellRoute` in go_router.

Typed props helper (generated by Next.js, no import needed):

```tsx
export default function RootLayout({ children }: LayoutProps<'/'>) { ... }
```

## 5. Dynamic routes: `[id]`

```tsx
// app/recipes/[id]/page.tsx
export default async function RecipePage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params            // ⚠️ params is a Promise in Next.js 15+ → await it
  const recipe = await getRecipe(id)
  return <h1>{recipe.title}</h1>
}
```

Or with the generated helper type (it knows the folder has `[id]`):

```tsx
export default async function RecipePage(props: PageProps<'/recipes/[id]'>) {
  const { id } = await props.params
}
```

More patterns:

| Folder             | Matches                                  | `params`                         |
| ------------------ | ---------------------------------------- | -------------------------------- |
| `[id]`             | `/recipes/1`                             | `{ id: '1' }`                    |
| `[...slug]`        | `/docs/a`, `/docs/a/b/c`                 | `{ slug: ['a', 'b', 'c'] }`      |
| `[[...slug]]`      | also `/docs` (optional)                  | `{ slug: undefined }`            |
| `(marketing)`      | **route group** — NOT in the URL. Organises files or gives a group its own layout | — |
| `_components`      | **private folder** — never a route       | —                                |

A static folder wins over a dynamic one: `/recipes/new` goes to `recipes/new/page.tsx`, not `[id]`.

## 6. Search params: `?q=coconut&page=2`

In a **page**, read them from the `searchParams` prop (also a Promise):

```tsx
export default async function RecipesPage(props: PageProps<'/recipes'>) {
  const { q } = await props.searchParams
  const query = typeof q === 'string' ? q : ''     // could be string | string[] | undefined
  // ...
}
```

In a **Client Component**, use the hook:

```tsx
'use client'
import { useSearchParams } from 'next/navigation'
const searchParams = useSearchParams()
const q = searchParams.get('q')
```

## 7. Navigation

### `<Link>` — like React Router's `<Link>`, but `href` instead of `to`

```tsx
import Link from 'next/link'

<Link href="/recipes">All recipes</Link>
<Link href={`/recipes/${recipe.id}`}>{recipe.title}</Link>
<Link href={{ pathname: '/recipes', query: { q: 'tea' } }}>Tea recipes</Link>
```

Next.js automatically **prefetches** links that appear on screen, so clicking feels instant.

### `useRouter` — navigate from code (Client Components only)

```tsx
'use client'
import { useRouter, usePathname } from 'next/navigation'   // ⚠️ next/navigation, NOT next/router (old)

function BackButton() {
  const router = useRouter()
  const pathname = usePathname()          // current path, e.g. "/recipes/pol-roti"
  return <button onClick={() => router.back()}>Back from {pathname}</button>
}
// router.push('/recipes')     → Navigator.push
// router.replace('/login')    → pushReplacement
// router.back()               → Navigator.pop
// router.refresh()            → re-fetch server data for the current page
```

### `redirect` — on the server

```tsx
import { redirect } from 'next/navigation'

export default async function Dashboard() {
  const user = await getUser()
  if (!user) redirect('/login')           // works in Server Components and Server Actions
  // ...
}
```

### `<Form>` from `next/form` — search forms

```tsx
import Form from 'next/form'

<Form action="/recipes">                    {/* GET form → navigates to /recipes?q=... */}
  <input name="q" />
  <button>Search</button>
</Form>
```

It navigates client-side (no full reload), prefetches the target, and still works without JavaScript.

## 8. React Router (Vite) vs Next.js routing

| Task                    | React Router (Vite)                     | Next.js                                   |
| ----------------------- | --------------------------------------- | ----------------------------------------- |
| Define a route          | `<Route path="/about" element={...} />` | create `app/about/page.tsx`               |
| Shared layout           | layout route + `<Outlet />`             | `layout.tsx` + `{children}`               |
| Dynamic param           | `path="tasks/:id"` + `useParams()`      | folder `[id]` + `await params`            |
| Link                    | `<Link to="/x">`                        | `<Link href="/x">`                        |
| Navigate in code        | `useNavigate()`                         | `useRouter()` from `next/navigation`      |
| 404                     | `<Route path="*">`                      | `not-found.tsx`                           |
| Loading state           | your own state / Suspense               | `loading.tsx`                             |
| Search params           | `useSearchParams()`                     | `searchParams` prop or `useSearchParams()`|

<details><summary>Answers</summary>

1. `app/contact/page.tsx`.
2. `const { id } = await params` (params is a Promise).
3. `(shop)` is a route group → the URL is `/cart`. The second one is `/shop/cart`.
